# Attention

## 普通 Attention 中，中间结果（$S = Q \cdot K^T$、$P = \text{softmax}(S)$）为什么要保存到 HBM？

主要有两个原因：

### 1. 中间结果需要跨 kernel 传递

- $S = Q \cdot K^T$、$P = \text{softmax}(S)$、$O = P \cdot V$ 这三个运算通常由**三个独立的 kernel** 依次执行。
- 寄存器（以及共享内存）中的数据仅在当前 kernel 运行期间有效。一旦 kernel 结束或切换，其内容就会被回收或覆盖，无法跨 kernel 保留。
- 因此，前一个 kernel 的计算结果**必须先写回 HBM**，再由下一个 kernel 从 HBM 重新读入，才能继续后续计算。

### 2. 寄存器无法跨 block 生命周期存续

- 一个 grid 内的 block 数量往往远多于 SM 能同时驻留的数量。资源不足时，部分 block 只能排队，等待某个 SM 腾出资源后再被调度。
- 每个 block 执行完毕后，它占用的寄存器会被硬件**立即回收**，重新分配给之后调度到该 SM 的新 block。尚未被调度的 block 此时还未产生任何数据。
- 如果 block 在结束前只把结果留在寄存器里，而没有写回 HBM，这些数据就会随着寄存器被回收或覆盖而**永久丢失**。
- 寄存器的生命周期与“正在执行的 block”严格绑定——block 一旦结束，数据即失效。而 block 何时调度、落在哪个 SM 上，由硬件动态决定，kernel 无法控制。

---

## 寄存器溢出（Register Spill）

- **触发条件**：一个 warp 中所有线程需要保存的数据量，超过了分配给它们的寄存器容量。
- **处理方式**：编译器将放不下的数据转存到线程私有的 **local memory** 中。
- **存放位置**：local memory 实际上位于全局内存空间（即 HBM），但访问时会经过 L1/L2 缓存加速。
- **典型场景**：tile 尺寸设置过大，而每个 warp 分到的寄存器数量相对较少，导致部分计算结果或其他中间数据被“挤出”寄存器，被迫存入 local memory。
- **性能代价**：local memory 的访问延迟远高于寄存器，会明显拖慢 kernel 的执行速度。

# FlashAttention

## 前向传播过程

### 1. 分块与并行映射

#### 1.1 分块大小确定

根据每个 SM 的共享内存（SRAM）大小 $M$，确定两个分块大小：

- $B_r$：query 块行数，每个线程块处理的 query 行数。
- $B_c$：key/value 块行数，内层循环每次加载的 key/value 行数。

通常取 $B_c = \lceil M / (4d) \rceil$、$B_r = \min(\lceil M / (4d) \rceil, d)$，以保证片上能同时容纳 $Q_i$、$K_j$、$V_j$ 和中间矩阵 $S_{ij}$。

#### 1.2 并行映射

- 将 $Q$ 按行分为 $T_r = \lceil N / B_r \rceil$ 个块。
- 将 $K$ 和 $V$ 按行分为 $T_c = \lceil N / B_c \rceil$ 个块。
- **每个 thread block 负责一个 query 块 $Q_i$**。
- 所有 thread block 并行执行，每个 block 独立处理自己的 query 行，互不依赖。

### 2. 每个 Thread Block 的执行步骤

#### 2.1 加载 query 块

- 从 HBM 加载该 block 负责的 $Q_i$（形状 $B_r \times d$）到 SM 的 SRAM。
- $Q_i$ 在整个内层循环期间驻留在 SRAM 中。

#### 2.2 初始化片上状态

在寄存器（或部分 SRAM）中为当前 query 块的每一行初始化：

- 行最大值 $m$：长度 $B_r$，初始值为 $-\infty$。
- 行和 $\ell$：长度 $B_r$，初始值为 0。
- 输出累加器 $O$：形状 $B_r \times d$，初始值为 0（这里 $O$ 是**未归一化**的累加器，不除以 $\ell$）。

### 3. 内层循环：遍历所有 key/value 块

对于 $j = 1, 2, \dots, T_c$，重复以下步骤：

#### 3.1 加载 key/value 块

- 从 HBM 加载当前 key 块 $K_j$ 和 value 块 $V_j$（形状均为 $B_c \times d$）到 SRAM。
- 覆盖之前加载的 $K_{j-1}, V_{j-1}$。

#### 3.2 计算缩放点积得分

在 SRAM 中，使用 Tensor Core 执行矩阵乘法：

$$
S_{ij} = \tau \cdot (Q_i \cdot K_j^T)
$$

其中 $\tau = 1/\sqrt{d}$，结果 $S_{ij}$ 的形状为 $B_r \times B_c$，存储在 SRAM 中。

#### 3.3 应用掩码（可选）

- 如果存在 mask（如 causal mask 或 padding mask），对 $S_{ij}$ 的相应位置赋值为 $-\infty$（或一个非常大的负数）。
- 掩码操作在 SRAM 上完成。

#### 3.4 计算局部行统计量

对 $S_{ij}$ 的每一行（共 $B_r$ 行）并行计算：

**局部行最大值**：$\tilde{m}_{ij}$（长度 $B_r$），通过 warp 内线程协同求 max。

**减去局部最大值后的指数项**：

$$
\tilde{P}_{ij} = \exp(S_{ij} - \tilde{m}_{ij})
$$

其结果形状为 $B_r \times B_c$，保存在 SRAM 中。

**局部行和**：$\tilde{\ell}_{ij} = \text{rowsum}(\tilde{P}_{ij})$（长度 $B_r$）。

#### 3.5 在线更新全局统计量（online softmax）

逐元素计算新的全局最大值：

$$
m_{\text{new}} = \max(m, \tilde{m}_{ij})
$$

逐元素计算两个缩放因子：

$$
\alpha = \exp(m - m_{\text{new}}), \quad \beta = \exp(\tilde{m}_{ij} - m_{\text{new}})
$$

逐元素更新全局行和：

$$
\ell \leftarrow \alpha \odot \ell + \beta \odot \tilde{\ell}_{ij}
$$

其中 $\odot$ 表示逐元素乘法。以上向量操作都在寄存器中完成，不写回 HBM。

#### 3.6 更新输出累加器（未归一化）

先用 $\alpha$ 逐行缩放之前累积的未归一化输出 $O$：

$$
O \leftarrow \alpha \odot O
$$

然后计算当前块的贡献：

$$
\tilde{P}_{ij} \cdot V_j
$$

这是一个 $B_r \times B_c$ 乘 $B_c \times d$ 的矩阵乘法，使用 Tensor Core 完成。

将结果按行乘以 $\beta$ 后累加到 $O$：

$$
O \leftarrow O + \beta \odot (\tilde{P}_{ij} \cdot V_j)
$$

**注意：此处的 $O$ 未除以 $\ell$，保持未归一化状态。**

#### 3.7 更新局部状态

- 更新全局最大值：$m \leftarrow m_{\text{new}}$。
- 此时 $\ell$ 已经更新。
- 中间矩阵 $S_{ij}$ 和 $\tilde{P}_{ij}$ 不再需要，可以在 SRAM 中覆盖。

### 4. 内层循环结束后：最终归一化

当所有 $T_c$ 个 key/value 块都处理完毕后，在寄存器中对每行执行一次除法：

$$
O_{\text{final}} = O / \ell
$$

得到归一化的 attention 输出。

- 如果训练需要，将最终的 $\ell$（以及可能 $m$）写回 HBM 供反向传播使用。
- 将 $O_{\text{final}}$（形状 $B_r \times d$）从 SRAM/寄存器写回 HBM 中对应的输出行。

### 5. 多级并行与硬件协作总结

- **Grid 级**：多个 thread block 并行，每个处理不同的 query 块。
- **Block 级**：一个 thread block 内部顺序遍历所有 key/value 块，但每个块的计算由整个 block 协作完成。
- **Warp 级**：在矩阵乘法和逐行统计量计算中，不同 warp 划分输出 tile 的不同部分，利用 Tensor Core 的 MMA 指令高效执行。
- **寄存器**：保存每个线程负责的 $O$ 累加器部分、$m$、$\ell$ 等标量或向量片段。
- **SRAM**：存储 $Q_i$、当前 $K_j, V_j$、中间 $S_{ij}$、$\tilde{P}_{ij}$ 等。
- **HBM**：仅用于初始加载 $Q, K, V$ 和最终写回 $O$（以及训练时的 $\ell, m$），不存储中间矩阵 $S$ 或 $P$。

### 6. 关键优化点

- **中间矩阵不落地**：$S$ 和 $P$ 只在 SRAM 中产生和消费，不写回 HBM。
- **未归一化累加器**：内层循环中不进行除法，只在最后归一化一次，减少计算量。
- **Tensor Core 高效计算**：两个矩阵乘法都使用 Tensor Core，发挥混合精度吞吐优势。
- **数据复用**：$Q_i$ 驻留 SRAM，被所有 key/value 块复用；$K, V$ 块在 L2 中可能被不同 SM 共享。

## 附注：Online Softmax 的精髓（对前文的注解）

> 这一节不是主流程的一部分，而是对上面 FlashAttention 正文的注解/说明，用更直白的方式回答两个问题：**为什么 $S$ 和 $P$ 可以被“覆盖”？又靠什么保证结果仍然正确？**

### 1. 为什么 $S$ 和 $P$ 会被“覆盖”？

- 因为完整形状的 $S = Q K^T$ 和 $P = \text{softmax}(S)$ 的大小是 $N \times N$。
- 在长序列中（比如 $N = 2048$ 或更大），这个矩阵在显存（HBM）中非常大（$2048 \times 2048$ 就是 400 万个元素）。
- FlashAttention 的做法是：**每次只算一小块 $S_{ij}$ 和 $P_{ij}$（大小为 $B_r \times B_c$），用完就直接在片上内存（SRAM）里丢弃（被下一次循环覆盖），绝不写回显存。** 这就解决了显存爆炸的问题。

> **对应正文**：3.1 的内层循环分块加载，以及 6 的“中间矩阵不落地”。

### 2. 如果 $S$ 和 $P$ 被覆盖了，怎么保证结果正确？

关键就是利用**变量 $m$ 和 $\ell$ 来保留“记忆”**。可以把前面的过程想象成“边做累加、边扔草稿纸”，但必须用两个小本子记下关键信息：

- **变量 $m$（当前全局行最大值）**：记录“到目前为止，我看到的最大的分数是多少”。如果新算出来的块里有个更大的分数，$m$ 就更新；同时根据新旧最大值的差值 $e^{m_{\text{old}} - m_{\text{new}}}$，把前面已经算好并累加的结果按比例缩小。这保证了数值稳定性（防止指数溢出）。
- **变量 $\ell$（当前全局行和/分母）**：记录“到目前为止，所有被丢弃的块的指数和是多少”。当新块算完后，把新块的局部行和 $\tilde{\ell}_{ij}$ 累加进全局的 $\ell$。

> **对应正文**：3.4 的局部统计量，以及 3.5–3.6 中 $m$、$\ell$ 与 $\alpha$、$\beta$ 的在线更新。

### 3. 核心机制总结：用 $m$ 和 $\ell$ 代替 $S$ 和 $P$ 的“记忆”

可以概括为一句话：**$S$ 和 $P$ 只是临时工，用完即弃；$m$ 和 $\ell$ 是核心账本，记录着前面所有阶段的累积信息。**

正是因为 $m$ 和 $\ell$ 的存在，才能做到：

1. **只算一次**：每个 $Q_i$ 和 $K_j$ 只需要计算一次 $S_{ij}$。
2. **立即丢弃**：算完 $S_{ij}$ 和 $P_{ij}$ 后，不再需要它们，直接覆盖。
3. **等价更新**：通过 $m$ 和 $\ell$ 的缩放公式，每次更新后的未归一化结果 $O$，在数学上完全等价于“把所有 $S$ 和 $P$ 拼在一起做一次全局 Softmax”。

> **对应正文**：2.2 的状态初始化、3.5–3.6 的在线更新，以及 4 的最终归一化。

**总结**：由于 $S$ 和 $P$ 是算完就被覆盖的临时数据，FlashAttention 引入了 $m$（最大值）和 $\ell$（行和）这两个统计量，把前面所有“被丢弃”的块的贡献浓缩成了两个向量，从而在节省显存的同时，完美重构出最终的全局 Softmax 结果。
